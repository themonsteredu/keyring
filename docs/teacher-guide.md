# 교사용: 제작 준비와 2차시 운영

## 수업 목표와 범위

학생은 부품을 올바르게 연결하고, 키링 스튜디오의 꾸미기·블록코딩·날씨 화면을 사용합니다. **시작 이벤트, 순차 실행, 기다리기, 반복, 날씨 조건**을 블록으로 만들고 실제 ESP32에서 실행합니다. 실제 날씨와 연습용·오래된 예보를 구분하고, 우유팩 모양 케이스를 꾸민 뒤 자신의 프로그램을 설명합니다.

전자 부품은 ESP32-C3 SuperMini, SSD1306 I2C OLED, 점퍼선 4개, USB-C 케이블입니다. 우유팩 모양 케이스는 별도로 준비합니다. OLED에는 동물의 몸 대신 눈과 입이 나오므로 화면 창을 정면에 맞춥니다. 케이스의 실제 치수·고정 구조는 교사가 부품에 맞춰 확인합니다. 납땜과 배터리 조립은 수업 범위에 포함하지 않습니다. 보드나 OLED에 핀 헤더가 없다면 교사가 수업 전에 별도로 준비해야 하며, 학생이 무리하게 선을 끼워 고정하지 않도록 합니다. USB를 뺀 상태로 조립하고 교사가 배선을 확인한 뒤 전원을 연결합니다.

## 수업 전 준비

1. 실제 사용할 보드 한 대로 아래 실물 확인표를 먼저 완료합니다.
2. 모든 보드에 **눈·입 표정과 한글 날씨가 포함된 최신 통합 펌웨어**를 미리 업로드합니다. Vercel 화면만 새로 열어도 보드에 저장된 그림은 바뀌지 않습니다. 프로그램 API가 없는 예전 펌웨어에도 웹 변경만으로 `/api/program`이 생기지 않습니다. [업로드 안내](hardware-and-upload.md)의 ESP32C3 Dev Module·코어 3.3.7·Huge APP 설정을 유지합니다. 수업 시간에 드라이버·라이브러리 설치와 전체 업로드를 함께 진행하지 않아도 됩니다.
3. 각 보드의 `Keyring-XXXXXX` 이름을 기록하고 키트·학생 자리표에 같은 표시를 붙입니다. SSID의 마지막 여섯 글자는 기기별 MAC 주소에서 만들어집니다.
4. 스마트폰 브라우저에서 인터넷 없는 Wi-Fi에 연결을 유지하는 방법을 확인합니다. 자동으로 이동통신이나 다른 Wi-Fi로 전환하는 기기는 사전에 연습합니다.
5. 실제 수업 지역의 날씨 파일을 수업 직전에 받습니다. **실제 예보 파일과 샘플 파일을 이름과 안내 문구로 구분**합니다. 오래전에 받은 실제 파일을 최신 날씨라고 소개하지 않습니다.
6. 날씨 파일을 스마트폰의 파일 앱에서 고를 수 있는지 확인합니다. 휴대전화 운영체제·브라우저별 다운로드와 파일 선택 동작이 다를 수 있습니다.
7. 꾸미기 재료가 보드 접점을 단락시키지 않도록 절연 재료와 케이블 고정 방법을 준비합니다.
8. 예비 USB 데이터 케이블, 점퍼선, 정상 작동이 확인된 OLED·보드를 준비하면 고장 구분에 도움이 됩니다.
9. [온라인 키링 스튜디오](https://keyring-swart.vercel.app)에서 프로그램을 만든 뒤 JSON 내려받기, AP 연결 후 가져오기까지 연습합니다. Vercel 온라인 화면의 미리 실행이 실제 키링 실행을 뜻하지 않음을 시연합니다.
10. 기본 표정 순서 프로그램과 날씨 조건 도전 프로그램을 준비합니다. [블록코딩 안내](block-coding.md)의 예제를 사용할 수 있습니다.

기기의 AP에는 인터넷이 없습니다. 학생 휴대전화마다 AP 접속 중 이동통신을 사용할 수 있다고 가정하지 마세요. 수업에서는 **인터넷 연결 → 날씨 JSON 다운로드 → 키링 AP 연결 → 파일 가져오기** 순서를 기본으로 삼습니다. 학교 공유기·계정 정보를 기기에 입력할 필요는 없습니다.

30대 안팎의 AP를 동시에 켜면 2.4GHz 혼잡이 발생할 수 있습니다. 자리별로 한꺼번에 접속을 시도하기보다 소그룹 단위로 전원을 연결하고 저장을 마친 기기는 연결을 종료합니다. 기기별 Wi-Fi 이름을 확인해 친구 기기에 적용하지 않도록 지도합니다. 기본 암호는 모든 기기에서 동일하므로 수업 외 공개 장소에서 계속 켜 두지 않습니다.

## 1차시: 연결·표정·블록 순서, 40분

| 시간 | 활동 | 교사의 확인 |
| --- | --- | --- |
| 0~5분 | 완성 예시 관찰, 직접 선택과 프로그램 비교 | 순서를 정하면 기기가 스스로 실행함 |
| 5~15분 | 네 가닥 연결, 교사 확인, USB 전원 | GND→G, VCC→3.3V, SDA→GPIO4, SCL→GPIO5 |
| 15~20분 | 내 Wi-Fi 접속, 꾸미기에서 눈 모양·감정 저장 | 저장 성공 안내와 실제 OLED 일치 |
| 20~30분 | 시작→눈 모양→표정→기다리기→다른 표정 블록 | 위에서 아래 순차 실행, 기다리는 시간의 의미 |
| 30~35분 | 3번 반복 또는 전체 반복, 기기 저장·실행 | 미리 실행과 기기 실행 구분 |
| 35~40분 | USB 재연결, 시작·정지 비교, 결과 설명 | 실행 켠 프로그램의 처음부터 재시작, 정지 유지 |

## 2차시: 날씨 조건·꾸미기·공유, 40분

| 시간 | 활동 | 교사의 확인 |
| --- | --- | --- |
| 0~5분 | 준비한 날씨 파일 가져오기, 시각 맞추기 | 출처·업데이트 시각·샘플 구분 |
| 5~13분 | 비이면 슬픔, 아니면 행복 등 조건 프로그램 | 조건이 참/거짓일 때 실행되는 가지 예측 |
| 13~17분 | 프로그램 수정·저장, 시작·정지·수동 적용 | 직접 적용하면 프로그램 정지, 프로그램과 설정 저장 구분 |
| 17~31분 | 전원을 빼고 우유팩 케이스 꾸미기 | 화면 창·USB 단자 확보, 접점 절연과 케이블 고정 |
| 31~37분 | 프로그램 시연과 작품 발표 | 순서·기다리기·반복·조건 중 사용한 개념 설명 |
| 37~40분 | 전원 분리, 부품 정리 | USB 전원, 저장 프로그램과 시각 신뢰 구분 |

시간이 부족하면 교사가 배선을 사전에 준비합니다. 첫 차시의 표정 순서까지만 필수로 하고 반복·날씨 조건은 도전 과제로 나눌 수 있습니다. 날씨 API 이용이나 파일 공유가 막히면 명시적인 연습용 샘플로 데이터 표시를 익힙니다. 조건 분기의 샘플·오래된 예보·시계 미확인 처리 정책은 [블록코딩 안내](block-coding.md)를 따르며, 연습 결과를 실제 예보 판단으로 설명하지 않습니다.

시작 이벤트는 프로그램이 실행을 시작하는 지점입니다. 반복은 이미 정한 명령을 다시 실행하는 구조이며, 기다리기는 OLED 표정을 볼 시간을 만드는 명령입니다. 날씨 조건 블록은 데이터를 새로 다운로드하지 않습니다. 조건은 샘플·오래된 예보·시계 미확인 상태여도 저장된 코드를 사용하고, 날씨가 없으면 아니면 가지로 갑니다. 이 조건의 결과와 인터넷에서 실제 새 예보를 받는 일을 구분해 설명하세요.

## 실물 확인표

아래 항목은 클라우드 빌드로 확인할 수 없습니다. 수업 전 실제 부품으로 수행하고 결과를 기록합니다.

| 확인 항목 | 합격 기준 | 결과 기록 |
| --- | --- | --- |
| 배선 | GPIO4/5를 유지하고 VCC 3.3V, GND 공통 | 미확인 |
| 업로드·부팅 | 지정 보드·코어에서 업로드 성공, 부팅 로그 확인 | 미확인 |
| OLED | 128×64 화면에서 눈·입이 선명하고 반복 깜빡임·빈 화면 없음 | 미확인 |
| 30가지 조합 | 5눈 모양×6감정 구분, 잘림·좌우 뒤집힘 없음 | 미확인 |
| 미리보기 일치 | 같은 눈 모양·감정에서 웹과 OLED 모양이 같음 | 미확인 |
| 설정 저장 | 적용 성공 후 USB 재연결해 같은 설정 복원 | 미확인 |
| 블록 순서 | 눈 모양·감정·기다리기가 연결 순서대로 실제 OLED에서 실행 | 미확인 |
| 블록 반복·조건 | 지정 횟수 반복과 날씨 조건의 참/거짓 가지가 예상대로 실행 | 미확인 |
| 프로그램 저장 | 실행을 켠 프로그램은 전원 재연결 후 첫 명령부터 실행 | 미확인 |
| 프로그램 정지 | 정지 후 재부팅해도 자동 실행하지 않으며 수동 설정도 프로그램을 멈춤 | 미확인 |
| 프로그램 파일 | 온라인에서 내려받은 JSON을 AP 화면에서 가져와 실제 실행 | 미확인 |
| 실패 안내 | 기기 연결을 끊으면 저장 성공으로 오해시키지 않음 | 미확인 |
| 실제 날씨 | 준비한 실제 파일 저장, 큰 온도·웃는 아이콘·한글 상태·받은 시각·24개 시간별 예보 확인 | 미확인 |
| 인터넷 단절 | 모바일 인터넷 없이도 저장된 예보 표시 | 미확인 |
| 전원 재연결 | 저장 예보 유지, 시간 미확인 표시, 접속 후 시간 회복 | 미확인 |
| 오래된 데이터 | 3시간 초과 파일이 최신으로 표시되지 않음 | 미확인 |
| 샘플 | OLED와 웹 모두 샘플 표시를 유지 | 미확인 |
| 초기화 | 확인 후 기본 설정 복원 및 날씨 삭제 | 미확인 |
| 장시간 관찰 | 수업 시간 동안 과열·비정상 재부팅·화면 이상 없음 | 미확인 |
| 꾸미기 | 우유팩 창에서 전체 화면이 보이고, 모루 철사와 접점이 닿지 않으며 화면·단자에 힘이 가해지지 않음 | 미확인 |

자동 테스트와 ESP32-C3 타깃 빌드는 소프트웨어 검증입니다. 사용자가 기존에 확인한 `OLED OK` 출력은 배선·OLED 통신의 선행 확인이며 이번 통합 펌웨어의 위 항목을 대신하지 않습니다.

## 날씨 서비스 사용 판단

Open-Meteo 무료 API는 비상업적 이용 조건을 확인해야 합니다. 특히 유료 교육 상품이나 판매용 키링에 포함할 경우 해당 용도가 허용된다고 임의로 판단하지 말고 [공식 약관](https://open-meteo.com/en/terms)을 검토합니다. 트래픽 제한과 서비스 가용성은 바뀔 수 있으므로 수업 직전에 확인하고 파일 가져오기와 샘플을 준비합니다. 날씨 정보는 학습용이며 위험 상황의 판단 근거로 사용하지 않습니다.

이 프로젝트의 기본 화면은 위치를 도시 목록으로 선택하며 GPS 접근을 필수로 요구하지 않습니다. 학교·학생 주소 같은 개인정보를 입력할 필요가 없습니다. 키링 AP는 로컬 HTTP를 사용하고 공용 수업 암호를 제공하므로 민감한 정보를 다루는 시스템으로 사용하지 않습니다.

## 수업 후

프로그램 자동 실행을 원하지 않으면 블록코딩 화면에서 정지하고 기기 저장 상태를 확인합니다. 실행 상태로 저장된 프로그램은 다음 부팅에서 처음부터 실행합니다. 학생별 설정을 유지하려면 초기화하지 않고 전원을 분리합니다. 다음 수업에서 저장된 날씨가 남아 있더라도 새 파일을 받아 업데이트 시각을 확인하세요. 다른 학생에게 재배부할 때는 교사가 초기화합니다. USB 케이블·모루 재료·접점 상태를 확인하고 전원이 없는 상태로 보관합니다.
