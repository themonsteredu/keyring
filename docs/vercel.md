# Vercel 웹앱 배포

Vercel에는 `web/`의 스마트폰용 웹앱을 배포합니다. 브라우저에서 JavaScript가 실행되어 꾸미기·블록코딩·날씨 화면, 프로그램 미리 실행과 JSON 파일 다운로드를 제공합니다. 서버 프로그램이 필요 없는 정적 배포 방식입니다. ESP32 펌웨어를 빌드하거나 업로드하는 작업은 별개입니다.

## 배포 설정

저장소 루트의 `vercel.json`은 프레임워크 자동 감지를 끄고, 설치와 빌드를 생략하며, 출력 디렉터리를 `web`으로 지정합니다. 따라서 루트 `package.json`의 `npm run build`가 실행되어 ESP32 도구를 설치하거나 펌웨어를 컴파일하지 않습니다. `.vercelignore`는 웹 파일과 배포 설정만 업로드하도록 제한합니다. 펌웨어·테스트·도구·로컬 캐시는 웹 공개 디렉터리에 포함하지 않습니다.

Blockly 편집기와 한국어 메시지는 로컬 자산으로 배포합니다. 외부 스크립트나 CDN 폰트는 사용하지 않습니다. Blockly의 Apache 2.0 라이선스 고지도 유지합니다. 콘텐츠 보안 정책은 실제 날씨를 받는 `https://api.open-meteo.com` 연결을 허용합니다. 지문이 없는 파일을 변경해 배포할 때 이전 파일이 남지 않도록 자산을 재검증하도록 설정했습니다.

## CLI에서 배포하기

Node.js가 준비된 저장소 루트에서 Vercel CLI를 사용합니다. 기존 프로젝트 연결 정보가 있으면 해당 프로젝트를 사용하고, 없다면 배포할 계정·팀과 프로젝트를 연결합니다.

```sh
cd /workspace/keyring
npx vercel login
npx vercel --prod
```

이미 사용 가능한 인증이 있으면 다시 로그인할 필요가 없습니다. 인증 토큰은 채팅이나 Git 파일에 넣지 않고, Vercel의 로그인 절차 또는 실행 환경의 안전한 비밀 값 설정을 사용합니다. `.vercel/`의 로컬 프로젝트 연결 정보를 Git에 커밋하지 않습니다. 배포가 완료되면 CLI가 실제 URL을 출력합니다.

Vercel 대시보드에서 저장소를 가져올 때는 Root Directory를 저장소 루트로 두어 `vercel.json`이 적용되도록 합니다. Framework는 Other이며, 출력 디렉터리는 `web`입니다. 계정에 이미 다른 프로젝트가 연결되어 있다면 기존 프로젝트를 덮어쓰기 전에 대상이 이 키링 프로젝트인지 확인합니다.

## 온라인 화면에서 기기에 옮기기

Vercel의 HTTPS 주소는 학생용 온라인 꾸미기·블록코딩과 날씨 준비 화면입니다. ESP32의 `/api/state` 등 기기 API는 이 서버에 없으므로 화면에 **미리보기 모드**가 표시되고 기기에 적용하는 버튼은 비활성화됩니다. 이것은 배포 오류가 아닙니다.

온라인 HTTPS 페이지에서 ESP32의 HTTP 사설 주소로 직접 저장하는 방식은 혼합 콘텐츠·브라우저 사설 네트워크 접근 제약과 스마트폰의 Wi-Fi 전환 때문에 지원하지 않습니다. 다음 절차를 사용합니다.

1. 인터넷이 되는 상태에서 실제 배포 URL을 엽니다.
2. 지역을 고르고 **실제 날씨 받기**를 누릅니다.
3. 출처와 업데이트 시각을 확인하고 **날씨 파일 내려받기**를 누릅니다.
4. 스마트폰을 내 키링의 `Keyring-XXXXXX` Wi-Fi로 바꾸어 연결합니다.
5. 일반 브라우저에서 `http://192.168.4.1`을 열고 **미리 받은 날씨 파일 불러오기**를 사용합니다.
6. 저장 확인 후 **친구 / 날씨 / 번갈아 보기** 중 원하는 화면을 적용합니다.

블록 프로그램도 파일로 옮깁니다.

1. 온라인 화면의 **블록 코딩**에서 프로그램을 만들고 브라우저에서 미리 실행합니다.
2. **코드 파일 저장**으로 `keyring-program.json`을 내려받습니다. 날씨 파일과 혼동하지 않습니다.
3. 내 키링 AP로 바꾸어 연결하고 `http://192.168.4.1`의 **블록 코딩**에서 **코드 불러오기**를 사용합니다.
4. **키링에 저장**을 누르고 기기 저장·실행 결과와 실제 OLED의 순서를 확인합니다.

실행을 켠 프로그램은 기기에 저장한 직후 실행하고 다음 부팅에도 처음부터 실행합니다. 기존 펌웨어에 프로그램 API가 없다면 새 통합 펌웨어를 먼저 업로드해야 합니다. 상세한 프로그램 계약과 예제는 [블록코딩 안내](block-coding.md)에 있습니다.

캐릭터와 감정 저장도 키링 Wi-Fi에 연결한 기기 화면에서 합니다. Vercel 계정이나 개인 정보를 학생이 입력할 필요는 없습니다. 날씨 API의 비상업 무료 이용 조건과 예보·시각 처리 방식은 [날씨 안내](weather.md)를 따릅니다.

## 배포 뒤 확인

- 실제 배포 주소에서 한국어 페이지가 열리고 128×64 캐릭터가 움직이는지 확인합니다.
- `/app.js`, `/weather.mjs`, `/style.css`, `/sprites.json`과 로컬 Blockly 자산이 정상 응답하고 JavaScript 모듈이 실행되는지 확인합니다.
- 꾸미기·블록코딩·날씨 탭과 블록 편집기가 열리고 프로그램 미리 실행·JSON 내려받기가 가능한지 확인합니다.
- 온라인 배포의 `/api/state`는 404여야 하며, 모의 기기나 저장 완료처럼 표시하면 안 됩니다.
- 실제 날씨 수신 성공과 인터넷 요청 실패 안내를 구분해 확인합니다. 샘플은 항상 연습용입니다.
- 실제 ESP32의 AP 연결·저장·OLED 검증은 [실물 확인표](teacher-guide.md)로 별도로 확인합니다.

배포 설정 파일을 작성한 것과 Vercel에 게시가 완료된 것은 다릅니다. 배포 완료 여부는 CLI의 성공 결과와 실제 URL 응답으로 판단합니다.

## 이 클라우드에서의 현재 결과

Vercel CLI 65.2.0 설치와 설정·정적 자산 경로 검사를 완료했습니다. 기존 Vercel 인증이나 프로젝트 연결이 없으며 `vercel whoami`에서 로그아웃 상태를 확인했습니다. CLI가 안내하는 `vercel deploy --temporary`도 시도했으나 이 실행에서는 임시 배포가 제공되지 않아 인증 필요 오류로 종료했습니다. 실제 배포 URL은 아직 생성되지 않았습니다.

Vercel API 접속은 현재 클라우드 네트워크 정책에서 403으로 차단됩니다. 환경 설정 초안에 `api.vercel.com`, `vercel.com`, `*.vercel.app` 접근과 `VERCEL_TOKEN` 비밀 값 요구사항을 추가했습니다. 토큰은 채팅이나 소스 파일 대신 환경 설정의 비밀 값으로 입력합니다. 변경 사항을 검토·저장하고 환경을 게시한 뒤 런타임에 적용되면 인증과 배포를 다시 검증해야 합니다. 이 초안 저장만으로 배포가 수행되는 것은 아닙니다.
