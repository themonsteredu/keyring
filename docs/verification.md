`bash tools/test.sh`, `npm run test:e2e`, `bash tools/build.sh`를 실행했습니다. 네이티브 검사와 날씨 픽셀 비교는 AddressSanitizer·UndefinedBehaviorSanitizer를 사용했습니다. 브라우저의 음수 반올림을 OLED와 맞춘 뒤 해당 흐름, 최종 빌드와 생성 자산·ZIP 일치를 다시 확인했습니다.

최종 플래시 **1,341,115 / 3,145,728바이트**, 정적 RAM **41,484 / 327,680바이트**. 빌드 옵션은 `esp32:esp32:esp32c3:CDCOnBoot=cdc,FlashSize=4M,PartitionScheme=huge_app`입니다. 실제 업로드에서도 **Huge APP (3MB No OTA/1MB SPIFFS)**을 선택합니다. SDA GPIO4·SCL GPIO5를 유지했습니다.

## 화면과 데이터

승인된 시안의 여섯 표정을 도톰한 흰 픽셀로 구현했습니다. 기본 말랑눈은 웃는 눈과 W 입, 반짝이는 눈, 졸린 눈, 눈물, 화난 눈썹, 하트 눈을 사용합니다. 동물 몸·귀·얼굴 테두리는 없습니다. 기존 5개 스타일 ID와 블록 파일을 계속 읽을 수 있습니다. 브라우저에서 30조합의 실제 Canvas 픽셀과 C++에서 내보낸 atlas를 비교했습니다.

일반 날씨 OLED는 웃는 아이콘·정수 온도·습도만 표시합니다. 연습 데이터·지난 예보·시각 미확인일 때 짧은 한글 상태를 표시합니다. 이후 24개 시간별 예보도 한 화면에 하나씩, 날짜·시각과 함께 표시합니다. C++와 브라우저의 505프레임 비교는 모든 페이지, 상태, 아이콘 6종, 깜빡임, 음수 온도, 습도 0~100%와 누락, 윤일·연도 전환을 포함합니다.

실제 API 요청에 현재·시간별 `relative_humidity_2m`를 추가했습니다. 수신 습도는 0~100의 정수로 검증하고 저장·JSON 내보내기·불러오기·모의 재부팅 뒤에도 유지됩니다. 기존 파일에서 누락된 습도는 `--%`이며 0%로 만들지 않습니다. 웹 숫자의 `-0.5° → -1°` 반올림도 OLED와 일치합니다.

대시보드는 여섯 표정을 먼저 보여 줍니다. 눈 모양, 예보, 파일 기능, 받은 시각·출처와 도움말은 펼쳐서 봅니다. 접힌 항목을 실제로 열어 선택·저장·가져오기를 검사했습니다. 모바일 가로 넘침, 블록 코딩 중 미리보기·실행 버튼 표시, 저장 실패, 오래된 예보, 시각 미확인도 검증했습니다.

## 실물에서 확인할 항목

실제 보드 업로드·OLED 표현·AP 연결·물리 NVS와 전원 분리 후 복원·깜빡임·전력 소비는 클라우드에서 검증하지 못했습니다. 앞선 `OLED OK`는 사용자가 확인한 별도 하드웨어 결과입니다. [교사용 확인표](teacher-guide.md)에 따라 확인합니다. 배터리와 충전 회로는 아직 미정이며 USB 전원만 대상으로 합니다.

실제 API 수신 성공은 상시 가용성·예보 정확도를 보장하지 않습니다. GitHub Actions의 원격 실행 결과는 이 기록에서 확인하지 않았습니다. 모의 재부팅 검증은 실제 ESP32 NVS와 구분합니다.
