# 빌드·테스트 실행 기록

검증일: 2026-10-23. 대상: ESP32-C3 SuperMini, ESP32C3 Dev Module, Arduino ESP32 Core 3.3.7. 실제 USB 장치가 연결되지 않은 Linux 클라우드에서 실행했습니다.

| 검사 | 실행 결과 |
| --- | --- |
| 공식 체크섬 기반 도구 설치 | 성공. 별도의 빈 설치 경로에서도 설치와 타깃 컴파일 성공 |
| `bash tools/setup.sh` 재실행 | 성공. 고정 도구 재사용, `npm ci` 성공 |
| `bash tools/test.sh` | 성공. 아래의 C++·JavaScript·HTTP 검사 및 생성 자산 일치 검사 완료 |
| C++ 설정·날씨·시계 규칙 | 75개 검증 통과. AddressSanitizer·UndefinedBehaviorSanitizer 사용 |
| C++ 렌더러 | 960프레임의 결정성, 30조합 구별, 깜빡임·움직임, 비트 순서와 버퍼 경계 통과 |
| JavaScript 날씨 | 8개 테스트 통과, 실패·건너뜀 없음 |
| Python 모의 HTTP API | 7개 테스트 통과. 실제 ESP32 실행 결과와 구분 |
| `npm run test:e2e` | 시스템 Chromium에서 10개 통과, 실패·건너뜀 없음 |
| 웹·OLED 픽셀 일치 | 브라우저에서 30개 캐릭터·감정 조합의 픽셀을 펌웨어 프레임과 비교하여 통과 |
| `bash tools/build.sh` | ESP32-C3 RISC-V용 실제 교차 컴파일 성공 |

최종 빌드의 스케치 사용량은 플래시 **1,150,449바이트 / 3,145,728바이트**, 정적 RAM **41,036바이트 / 327,680바이트**입니다. 보드 옵션은 USB CDC On Boot Enabled, Flash Size 4MB, Huge APP입니다. 원본을 수정하면 사용량은 달라질 수 있습니다.

브라우저 검사는 설정 적용과 재조회·새로고침 복원, 저장 실패 시 성공을 표시하지 않는 처리, 명시적인 샘플 구분, 초기화, 잘못된 파일 거부, 인터넷 요청 실패, 360px 화면에서 가로 넘침 없음과 동작 줄이기 설정을 확인했습니다. 추가로 전원 재시작을 모의한 뒤 시간 동기화가 실패하면 시각 확인 필요로 표시되는지, 페이지를 연 채 3시간을 넘기면 오래된 예보로 바뀌는지, 이때 학생의 미저장 선택이 보존되는지 검사했습니다.

출력은 `.build/firmware/`의 `.bin`, `.elf` 등이며 Git에 포함하지 않습니다. Arduino IDE용 소스와 생성된 웹 헤더는 `firmware/Keyring/`에 모두 포함됩니다. GitHub Actions 검사 구성도 추가했지만 **원격 Actions 실행 결과는 아직 없습니다.**

## 남은 확인

- 이 통합 펌웨어를 실물 보드에 업로드하고 OLED 그림·표정·눈 깜빡임을 확인해야 합니다. 기존 `OLED OK` 성공은 사용자가 앞서 확인한 별도 하드웨어 결과입니다.
- 실제 ESP32 NVS 저장 후 USB 전원 분리·재연결 복원, 스마트폰의 AP 연결, OLED 떨림과 전력 소비를 확인해야 합니다. 네이티브·모의 HTTP 테스트가 이 항목을 대신하지 않습니다.
- Open-Meteo 실제 API 응답은 이 클라우드 네트워크 정책의 403 차단으로 받지 못했습니다. 실제 API 요청 코드는 구현했고, 공식 조건·데이터 계약·오류 처리와 변환 로직은 확인했습니다. API 도메인 허용 후 실제 날씨 파일 수신과 장치 가져오기를 확인해야 합니다. 연습용 데이터를 실제 수신 결과로 기록하지 않았습니다.
- 배터리와 충전 회로는 미정이며 USB 전원만 대상으로 합니다.

실물 검증은 [교사용 확인표](teacher-guide.md)에 따라 진행합니다.
