# 날씨 데이터와 시간 처리

## 데이터 흐름

```text
인터넷이 되는 스마트폰/PC
    └─ Open-Meteo 실제 예보 요청
          └─ 24개 시간별 예보를 공통 JSON으로 변환
                ├─ 온라인 상태에서 JSON 파일 다운로드
                │     └─ 키링 AP로 연결을 바꾼 뒤 파일 가져오기
                └─ 휴대전화가 인터넷을 유지할 수 있으면 기기로 바로 전송
                      └─ ESP32 NVS 저장 → 인터넷이 끊겨도 OLED 표시
```

ESP32 펌웨어는 기본적으로 설정용 Wi-Fi AP만 제공합니다. 학교 공유기 암호를 받거나 스스로 외부 API에 접속하는 STA 모드는 포함하지 않습니다. 인터넷 없는 AP에 접속한 스마트폰이 반드시 이동통신도 사용할 수 있는 것은 아니므로 파일 가져오기가 기본 대안입니다.

## 실제 API와 이용 조건

사용하는 실제 서비스는 [Open-Meteo](https://open-meteo.com/)의 Forecast API입니다. API 키 없이 비상업적 무료 범위에서 사용할 수 있으며, 상업적 이용과 사용량 제한은 [공식 이용약관](https://open-meteo.com/en/terms)을 따라야 합니다. 무료 서비스에는 가용성 보장이 없으므로 수업 전에 실제 파일을 준비하고 샘플도 별도로 준비합니다. 유료 수업·상품 판매 등의 이용 가능 여부를 임의로 단정하지 않습니다.

2026-10-23에 [공식 약관 소스](https://github.com/open-meteo/open-meteo-website/blob/main/src/routes/en/terms/+page.svelte)에서 비상업 무료 조건, 하루 10,000회 미만·시간 5,000회·분 600회 호출 제한과 무보증 조건을 확인했습니다. [공식 프로젝트 안내](https://github.com/open-meteo/open-meteo#readme)에서도 키 없는 비상업 무료 이용과 데이터 CC BY 4.0을 확인했습니다. 한 번의 버튼 조작으로 한 번 요청하며 자동 반복 요청은 하지 않습니다. 약관은 변경될 수 있으므로 수업 배포 전 다시 확인합니다. 이번 클라우드에서는 실제 날씨 API 도메인 접속이 네트워크 정책으로 차단되어 실시간 응답 수신은 별도 확인 항목으로 남겼습니다.

사용 데이터는 다음과 같습니다.

| 요청 항목 | 용도 |
| --- | --- |
| `latitude`, `longitude` | 선택한 지역 좌표 |
| `current=temperature_2m,weather_code` | API가 제공하는 현재 기온과 WMO 날씨 코드 |
| `hourly=temperature_2m,weather_code` | 한 시간 간격 기온과 날씨 코드 |
| `forecast_days=2` | 다음 정시부터 24개 미래 시간 슬롯 확보 |
| `timeformat=unixtime`, `timezone=GMT` | 모호하지 않은 UTC 초 단위 시각 |

예시 요청:

```text
https://api.open-meteo.com/v1/forecast?latitude=37.5665&longitude=126.9780&current=temperature_2m,weather_code&hourly=temperature_2m,weather_code&forecast_days=2&timeformat=unixtime&timezone=GMT
```

Open-Meteo의 현재 날씨도 모델 기반 데이터이며 현장 센서 실측이라고 주장하지 않습니다. 화면에는 [Open-Meteo](https://open-meteo.com/) 출처와 [CC BY 4.0](https://open-meteo.com/en/licence) 안내를 유지합니다. 원본 데이터를 표시용 JSON과 아이콘으로 변환했다는 점을 함께 알립니다.

## 시간별 예보의 의미

새 파일에는 다음 정시부터 24개 미래 시간 슬롯을 담습니다. 예를 들어 14시 35분에 받으면 15시부터 다음 날 14시까지의 24개 시간별 예보입니다. 모든 항목은 UTC 기준 3,600초 간격으로 이어집니다. 현재 기온은 별도의 현재 날씨 자료로 보여 줍니다. 가져온 이전 파일은 원래의 시각을 유지하므로 예보 표의 날짜와 업데이트 시각을 함께 확인합니다.

웹은 `Asia/Seoul` 시간대로 표시합니다. OLED도 한국 시각(KST, UTC+9)을 사용합니다. JSON에 저장되는 숫자는 UTC Unix 초입니다. 브라우저가 다른 국가의 시간대로 설정되어 있어도 표시 기준은 한국 시각입니다.

기본 도시 선택지는 서울·부산·인천·대전·광주·대구·제주입니다. 기본 아이콘은 맑음·흐림·비·눈입니다. WMO 코드를 검증하며, OLED는 안개·뇌우를 추가로 구분할 수 있습니다. 웹의 간단한 네 가지 그림은 안개를 흐림에, 뇌우를 비에 묶어 보여 줄 수 있습니다. 숫자와 시각을 함께 확인합니다.

## 저장과 재부팅

날씨 JSON은 ESP32 내부 NVS에 저장합니다. 전원을 껐다 켜도 마지막 예보와 그 파일의 `fetchedAt`은 남습니다. 파일을 가져온 시각을 새 업데이트 시각으로 덮어쓰지 않으므로 오래된 파일을 다시 가져와도 새 예보가 되지 않습니다.

현재 하드웨어에는 배터리 백업 RTC가 없고, 펌웨어는 AP만 사용하므로 NTP를 필수 전제로 두지 않습니다. 대신 스마트폰 웹 화면이 UTC 현재 시각을 보내고, 기기는 이번 부팅의 단조 증가 시간과 결합해 시계를 진행합니다. 사용자 휴대전화의 시계가 틀리면 그 오차가 반영될 수 있습니다.

**재부팅하면 시계의 신뢰 상태는 항상 해제됩니다.** 저장된 업데이트 시각을 현재 시각처럼 복원하지 않습니다. 스마트폰에서 설정 화면을 열면 자동으로 시간 동기화를 시도하고, **휴대폰 시각 맞추기** 버튼으로 다시 맞출 수도 있습니다. 동기화에 성공하면 이번 부팅에 한해 현재 시각을 알게 됩니다. 설정 저장 여부와 시간 동기화 여부는 별개의 상태입니다.

| 상태 | OLED 문구 | 의미 |
| --- | --- | --- |
| `missing` | `NO WEATHER` | 저장된 날씨가 없음 |
| `sample` | `SAMPLE` | 연습용 데이터이며 실제 날씨가 아님 |
| `clock-unknown` | `TIME UNKNOWN` | 예보는 있지만 현재 시각의 신뢰 여부를 모름 |
| `stale` | `OLD FORECAST` | 3시간 초과, 예보 범위 밖, 또는 시각 불일치 |
| `fresh` | `SYNCED` | 이번 부팅에서 시간을 맞췄고 갱신·예보 범위가 유효함 |

샘플 데이터는 시계를 맞추거나 오래 기다려도 실제 날씨로 바뀌지 않습니다. 시간 미확인 상태에서는 남은 예보가 최신인지 판단할 수 없으므로 저장된 시각과 미확인 표시를 유지합니다. `SYNCED`도 연속 실시간 연결이라는 뜻은 아닙니다. 마지막 업데이트 이후의 저장된 예보입니다.

## 날씨 JSON 계약

스키마 버전은 `1`입니다. 이름·좌표·시각·온도·날씨 코드를 검사하고, 24개 예보가 연속인지 확인한 뒤 저장합니다. 오류 파일은 기존 저장 데이터를 대체하지 않아야 합니다.

| 필드 | 자료형 | 설명 |
| --- | --- | --- |
| `schema` | 정수 | `1` |
| `source` | 문자열 | 실제 `open-meteo`, 연습용 `sample` |
| `location.name` | 문자열 | 표시할 지역 이름, 최대 96 UTF-8 바이트 |
| `location.latitude` | 숫자 | -90~90 |
| `location.longitude` | 숫자 | -180~180 |
| `fetchedAt` | 정수 | API에서 받은 시각, UTC Unix 초 |
| `current.time` | 정수 | 현재 날씨의 기준 시각 |
| `current.temperature` | 숫자 | 섭씨, 유한한 값 |
| `current.code` | 정수 | 지원하는 WMO 날씨 코드 |
| `hourly` | 배열 | 정확히 24개, 각 항목은 `time`, `temperature`, `code` |

외부 파일의 `source` 문자열은 암호학적으로 검증된 출처 인증이 아닙니다. 수업에서는 이 프로젝트가 내려받은 파일이나 교사가 준비한 파일을 사용합니다. 인터넷 접속 실패를 감추기 위해 샘플을 `open-meteo`라고 바꾸거나 `fetchedAt`을 현재 시각으로 고치지 않습니다.

## 수업에서 실패했을 때

- API 요청이 실패하면 캐릭터 설정은 계속 사용할 수 있습니다. 인터넷 연결을 확인하고 먼저 파일을 다운로드합니다.
- API 속도 제한이나 서비스 오류가 나면 자동으로 샘플을 실제 날씨처럼 대체하지 않습니다. 샘플 버튼은 연습용임을 읽고 직접 선택합니다.
- 저장 뒤 화면이 바뀌지 않으면 화면 모드가 캐릭터인지 확인하고 날씨 또는 자동 전환으로 바꿉니다.
- USB를 다시 연결한 뒤 시간 미확인이 나오면 스마트폰 설정 화면을 열어 시간을 다시 맞춥니다.
- 오래된 예보라면 실제 새 예보를 내려받습니다. 예전 파일의 날짜를 수정해 해결하지 않습니다.
